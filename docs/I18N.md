# Mosaic i18n architecture

> **Status:** Living document. v1.0.2.
> **Audience:** Frontend contributors adding or translating UI strings.

Mosaic uses `i18next` + `react-i18next` for all user-facing strings. The
configuration lives at `apps/web/src/lib/i18n.ts` and the translation files
live at `apps/web/src/locales/`.

For per-locale-file conventions and the **plural fallback pattern**, see
`apps/web/src/locales/README.md`. This document covers the higher-level
architecture.

## Supported locales (v1.0.2)

| Code | Name | Native name | Direction |
|---|---|---|---|
| `en` | English | English | LTR |
| `cs` | Czech | Čeština | LTR |

The supported set is declared in `apps/web/src/lib/i18n.ts::supportedLanguages`.
Adding a locale requires (1) a new `<code>.json` file, (2) a new row in
that array, and (3) language-picker entries.

## Boot path

1. `i18next` is initialised with both locales bundled (no async fetch — the
   JSON is webpack/Vite-imported synchronously so the first paint is never
   blocked on a network round-trip).
2. The browser language detector consults, in order:
   `localStorage['mosaic-language']` → `navigator.language` →
   `<html lang>`.
3. `nonExplicitSupportedLngs: true` means `cs-CZ` resolves to `cs`.
4. On any language change, the boot path synchronises **both**
   `document.documentElement.lang` and `document.documentElement.dir` so
   that screen readers and CSS logical properties pick up the change.

The `dir` sync is unconditional in v1.0.2 even though all current locales
are LTR. The list of RTL locale codes is maintained in
`apps/web/src/lib/i18n.ts` (currently the BCP-47 RTL set: `ar`, `arc`,
`dv`, `fa`, `ha`, `he`, `khw`, `ks`, `ku`, `ps`, `ur`, `yi`). Until a
locale from that set is added to `supportedLanguages` the runtime
behaviour is unchanged.

## Plural categories

Different locales have different CLDR plural categories. The two currently
supported locales:

- **`en`** — `one`, `other`.
- **`cs`** — `one`, `few` (2–4), `many` (used for non-integer like `1.5`),
  `other` (5+).

When a key's value differs across categories, **add an entry per category
that the UI realistically hits**, plus the bare key for fallback. See
`apps/web/src/locales/README.md` §"Plural fallback".

## Right-to-Left (RTL) status

| Concern | v1.0.2 status |
|---|---|
| `<html dir>` sync on language change | **Done** — `apps/web/src/lib/i18n.ts` synchronises both `lang` and `dir`. |
| RTL locale shipping | **Deferred to v1.1** — no RTL locale is in `supportedLanguages`. |
| Mirrored layout (logical CSS properties, flexbox row reversal) | **Partial / deferred** — components use logical CSS properties (`margin-inline-start` etc.) in new code; full sweep deferred to v1.1. |
| Mirrored icons (chevrons, back-arrows) | **Deferred to v1.1** — currently directional icons are not mirrored. |
| Mirrored map controls (Leaflet zoom, scale) | **Deferred to v1.1** — upstream Leaflet ships a partial RTL story. |

The deliberate split — sync the `<html dir>` infrastructure in v1.0.2 but
defer the UI sweep — means that introducing an RTL locale in v1.1 is purely
a translation + visual-sweep task; no boot-path change is required.

## Date / time / number formatting

Use `apps/web/src/lib/i18n-locale.ts::getActiveLocale()` to get the active
locale string for `Intl.DateTimeFormat`, `Intl.NumberFormat`, and the
`toLocale*String` family. Do **not** pass `navigator.language` directly —
that returns the browser's preference, not the user's chosen Mosaic
language.

## Testing

- `apps/web/src/lib/__tests__/i18n-locale.test.ts` covers `getActiveLocale`.
- Locale key-parity is asserted by a Vitest test that walks the `en.json`
  key set and confirms every other locale carries the same keys (with the
  intentional exception of plural-suffix keys, which may differ by locale).
- E2E coverage for language switching is in `tests/e2e/i18n.spec.ts`.
